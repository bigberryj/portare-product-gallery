# Product Setup Media Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Ship per-product setup pictures, a 15-second image sequence, real MP4 export, and uploaded video playback beneath the gallery description on Portare staging.

**Architecture:** Add isolated `_ppg_setup` product metadata and `PPG_Setup` PHP class; render inside the existing gallery copy column. Reuse WordPress Media Library for selected public product assets. Generate MP4 in the administrator's browser using Canvas/MediaRecorder (capability tested on the installed Chromium) rather than adding a new server renderer or paid provider. AI-inferred folding is explicitly deferred; never label fades as mechanical motion.

**Tech Stack:** Existing PHP/WooCommerce, native browser JS/CSS, WordPress media APIs. No new paid service, no source/builder-content rewrites.

## Scope/contract

- `_ppg_setup`: `enabled`0/1, `mode` pictures|sequence|video, `images` deduplicated positive raster attachment IDs max4, `heading` max120, `caption` max500, `motion`0/1, `video_id`, `poster_id`, `replace_illustrations`0/1. Defaults disabled/pictures/no replacement. Fixed duration15000ms; sequences/export require2–4 images.
- `PPG_Setup::config($id)`, `sanitize($raw)`, `render($id)`, `panel($id)`, `save($id)`, `init()`, `assets($hook)`; output retains stored data on uninstall/deactivate.
- Render `section.ppg-setup[data-ppg-setup][data-mode][data-product-id]` with `data-motion`, optional `data-replace-illustrations=1`; heading/caption escaped. `.ppg-setup-pictures` and images for pictures; `.ppg-setup-stage` with `.ppg-setup-frame` images and `.ppg-setup-play` for sequence; `video.ppg-setup-video[controls][playsinline][preload=metadata]` for video. Local `script.ppg-setup-data[type=application/json]` contains `{mode,images:[{id,src,alt}],motion,duration:15000,productId}` with JSON_HEX flags.
- Admin wrapper `.ppg-setup-admin` with data-product-id, data-upload-url and data-upload-nonce. Fields names `ppg_setup[...]`, marker `ppg_setup_present`, own nonce `ppg_setup_nonce` for action `ppg_setup_save_{id}`. IDs `ppg_setup_enabled`, `ppg_setup_mode`, `ppg_setup_heading`, `ppg_setup_caption`, `ppg_setup_motion`, `ppg_setup_video_id`, `ppg_setup_poster_id`, `ppg_setup_replace_illustrations`.
- Image list `.ppg-setup-list` with `li.ppg-setup-image[data-id][data-src][data-alt]`; hidden image ID fields, buttons `.ppg-setup-image-up/-down/-remove`. Add button `.ppg-setup-add-images`. Video and poster pick/clear `.ppg-setup-pick-video`, `.ppg-setup-clear-video`, `.ppg-setup-pick-poster`, `.ppg-setup-clear-poster`; hidden ID inputs carry `data-url` and selection labels `.ppg-setup-video-label`/`.ppg-setup-poster-label`.
- Admin preview button `.ppg-setup-preview-button`, preview output `.ppg-setup-preview`, export `.ppg-setup-export`, cancel `.ppg-setup-export-cancel`, download anchor `.ppg-setup-download`, save-to-library `.ppg-setup-use-video`. Status `.ppg-setup-admin-status`, error `.ppg-setup-admin-error`. No preview/export/upload button submits product Update. Unsupported MP4 recording is an explicit visible error, never mislabeled WebM.
- Ajax action `ppg_setup_upload`, form fields `product_id`, `nonce` (action `ppg_setup_export_{id}`), upload `setup_video`. Success `{success:true,data:{id,url}}`. Authenticate + edit product + upload_files + nonce, max25MB, MP4 magic/MIME+video metadata dimensions/duration checks (14–17sec, max1280x720), safe generated filename; reject all other formats, no remote URL fetching. Rate-limit expensive upload path; clear lock on appropriate failure. Store through WP media handling as intended public product media. Do not change product config until Update.
- Public image/video choices must resolve real local WP attachments, allowlisted raster/video MIME, sanitized stored text; no arbitrary media URLs or iframe embeds.
