## Shared template change found during preservation review
Template 11378 (`portare cocktail table product page`) was re-saved by Brizy during the authenticated QA product Update on Cocktail Table 11012: `brizy_data_version` 159 to 160, a new revision 14743, regenerated CSS class hashes and compiled-section bytes, and one authored Section (`w5VjPxx1HtX3`) now carries `showOnDesktop: "off"`, which hides that duplicate title/description section on desktop viewports (confirmed live at 1440px: `display:none`, height 0, while the gallery-bearing section stays visible with the setup area).

- Normalized compiled markup is byte-identical before and after (33861 bytes) once Brizy generated class hashes are masked, so no authored content was added, removed or reordered.
- The only semantic compiled change is the new desktop `display:none` rule for that section.
- The plugin cannot cause this: it writes product metadata only (`_ppg_setup`, `_ppg_config`, `_ppg_slides`) and never writes post content, Brizy templates or compiled sections. The write came from a Brizy editor/template save triggered by saving the product.
- The pre-change snapshot is stale by design, so the template was **not** restored: restoring would discard an operator editor save and can clobber newer work. The change is reported for Byron to confirm or revert in the Brizy editor.
